# 账号安全加固说明

## 本次代码改动

- CORS 来源改为环境变量 `CORS_ORIGINS` 的显式白名单。
- 仅当 `APP_ENV=development`（默认开发环境）且没有配置白名单时，才允许 localhost:3000 与 127.0.0.1:3000。
- 非开发环境未配置 `CORS_ORIGINS` 时，默认不允许任何浏览器来源；部署时必须显式配置官网的 HTTPS Origin。
- 增加 `X-CSRF-Token` 到允许请求头，为后续 Cookie 会话迁移预留。

## 部署配置

开发环境可不设置变量。生产环境示例：

```env
APP_ENV=production
CORS_ORIGINS=https://你的正式域名
```

多个可信来源用英文逗号分隔。只填写 Origin（协议 + 域名 + 可选端口），不要填写路径，也不要使用通配符。不要把本地开发地址加入生产白名单。

## 当前仍未完成（不可视为已具备生产安全性）

1. 当前登录原型使用 Bearer Token；本次没有声称已完成 HttpOnly Cookie 会话。
2. Cookie 会话启用前，必须同步实现 CSRF token 校验、Origin/Referer 校验、Secure、HttpOnly、SameSite、过期与服务端退出失效。
3. 注册邮箱验证、找回密码、一次性令牌哈希存储、令牌过期与重放保护仍待实现。
4. 注册、登录、密码重置和试用激活接口仍需服务端限流与防暴力尝试。
5. 生产部署仍需 HTTPS、密钥管理、数据库迁移、审计日志、备份和安全测试。

## 验收要求

- 开发环境 localhost 前端仍可访问 API。
- 生产环境未配置 CORS 白名单时，不接受跨域浏览器请求。
- 生产环境只接受明确配置的官网 Origin。
- CORS 不是身份认证或 CSRF 防护的替代品；服务端每个受保护接口仍必须独立验证用户身份和权限。
