# 视频发布平台集成策略

## 首批平台
1. 抖音
2. 红果短剧
3. 快手

## 统一发布流程
1. 用户选择平台并查看账号授权状态。
2. 系统检查视频规格、封面、标题、简介和必要元数据。
3. 用户确认发布内容与目标账号。
4. 若平台官方开放接口已获准且账号授权有效，则通过服务端适配器创建发布任务。
5. 保存平台返回的任务 ID、状态和错误码；允许用户刷新状态或按规则重试。
6. 若官方接口不支持该内容类型或尚未获准，展示官方入口和手动上传清单，不模拟用户操作。

## 适配器契约
每个平台适配器应实现：
- `get_capabilities()`：返回平台当前已核实的功能与限制。
- `get_authorization_url()`：仅对官方 OAuth/授权流程提供入口。
- `handle_oauth_callback()`：校验 state 并安全保存令牌。
- `validate_media()`：校验文件格式、大小、时长、画幅等已核实限制。
- `create_publish_job()`：创建官方发布任务；不支持时明确返回 unsupported。
- `get_publish_status()`：查询发布状态。
- `revoke_authorization()`：撤销或清除本地授权。

## 平台差异与合规
- 不假设三个平台均提供面向所有开发者的公开视频发布 API。
- 接口权限、内容类型、账号资质和审核条件可能变化，必须在实际接入前核对官方最新文档并完成平台审核。
- 红果短剧可能采用独立的内容投稿/版权合作流程，不将抖音接口能力推定为红果短剧能力。
- 不使用非官方私有接口、自动化登录、验证码绕过、Cookie 注入或模拟点击规避平台限制。
- 发布前由用户最终确认，禁止未经授权自动群发。
- 发布失败时保留用户文件与草稿，不擅自删除或重复发布。

## 当前状态
本文件仅定义产品与工程边界；尚未完成任何平台的开发者资质申请、OAuth 接入或真实发布验证。各平台接入状态必须以官方审核与实测为准。
